# AI Link：iOS 中国大陆与境外上架评估

调研日期：2026-10-04（中国标准时间）。基于当前工作区代码、线上隐私政策、Apple 官方规则、监管机关文件和苹果公开应用目录。风险等级为产品判断，不是审核通过率或正式法律意见。本次重点覆盖中国大陆、Apple 通用审核及欧盟要求，没有完成全球逐国法律审计，也未提交审核、登录 App Store Connect 或安装竞品实测。

## 结论与发行选择

AI Link 的“用户自带 API Key、配置多个模型服务、设备直接请求第三方、聊天本地保存”模式有明确的 iOS 上架先例。Apple 没有在本次核查的公开规则中全面禁止这种客户端。

| 发行范围 | 当前判断 | 决定性问题 |
| --- | --- | --- |
| 中国大陆之外的首发地区 | 模式可行，当前准备程度有中等风险 | 第三方 AI 数据同意、审核可测试性、线上隐私政策、真实设备验证 |
| 欧盟 | 可行，但须增加地区合规核查 | AI 透明度、GDPR 适用角色、DSA 交易商身份及联系方式 |
| 中国大陆，保留任意 API 和全部境外服务预设 | 高不确定性，暂不建议直接提审 | App 备案、AI 服务备案/应用登记适用性、内容治理、境外服务与数据流 |
| 中国大陆，明确限制服务范围并完成手续 | 有条件可行 | 实际服务/模型与登记一致，生成内容标识、反馈处置和数据保护落地 |

建议先完成境外首发准备，以美国等服务可用地区验证审核和产品体验；欧盟核查完成后再纳入。中国大陆另行确定产品范围和适用手续。只在境外商店发行并不当然排除中国法规：如果实际向境内公众提供服务，仍需评估中国监管要求。

目前无自有聊天中转服务器、无 AI Link 账号、密钥安全存储，有利于减少开发者集中持有数据和服务计费责任。但它们不能自动免除应用审核、第三方传输告知或当地监管要求。

Chatbox 的[官方产品说明](https://chatboxai.app/en)也明确支持自有 API Key。中国区商店文案列举 DeepSeek、Kimi、MiniMax、Qwen；美区目录文案列举 ChatGPT、Claude、Gemini。文案不同不能证明二进制有何地区限制，也不能反推出其备案材料、豁免或审核沟通内容。

“为什么没看到”的合理解释：商店地区不同；“AI 客户端/API client/BYOK”等名称比“多模型聊天”更容易命中；自备 Key、API 账单与模型配置提高使用门槛，面向普通消费者的即用订阅产品更显眼。最后一点是市场推断，未核实各开发者商业决策。Apple Watch 类似产品也已有先例，因此这不是空白品类。

## Apple 审核：模式和当前缺口

依据 [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)及[官方审核准备说明](https://developer.apple.com/app-store/review/)，需要关注：

- **数据授权，5.1.2(i)：**向第三方 AI 共享个人数据前须明确告知并获得明确许可。当前源码检索与服务保存路径未发现专门同意流程；`lib/privacy_screen.dart` 有说明，不能据此认定已完成授权。建议在首次请求前展示实际服务名、域名、数据类别；修改接收方后重新确认，支持撤回。覆盖文本上下文、提示词、自动标题、录音与朗读文字，以及手表独立请求。麦克风权限处理录音访问，不能替代向第三方发送的授权。
- **审核能实际使用，2.1：**提供有效、限额、可撤销的审核测试凭据及步骤，不能要求审核员自行开户充值；不要把生产 Key 写进安装包。
- **实用性，4.2：**本地话题、Markdown、多服务、语音和手表有实际价值，宜用真实演示证明。第三方内容安全、准确元数据和适当年龄分级仍需负责。
- **支付，3.1 与第三方服务，5.2.2：**自带服务凭据有先例，但不是付费功能绕开 IAP 的通用豁免。以后售卖客户端高级功能、模型额度或会员，须重新按地区核对收费设计；当前先保持不代售 API 额度、不引导站外充值的方案。

单人私有问答与公开 UGC 社区的场景不同；不能仅因 Apple 1.2 就断言必须实现社区用户封禁，也不能直接套用 Google Play 的 AI 举报规则。不过当前只有“关于 → 联系与反馈”邮件入口，没有逐条回答的安全反馈流程；增加用户主动选择内容的反馈入口和处置机制是合理改进，不能自动上传全部聊天。

**已确认的线上政策缺口：**2026-10-04 用 HTTP 请求读取[正式隐私政策](https://www.tools24.uk/app/ai-link/privacy)，状态为 200，政策生效日期为 2026-09-29；正文只声明 Android/Wear OS，手表只介绍 Android Keystore。须补充 iOS/watchOS、Apple Watch Keychain、WatchConnectivity 密钥同步、手表优先请求/手机兜底、两端分别删除。语音发送方式也需与当前手势决定的流程一致。

**隐私标签要单独核查：**[Apple 的 App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)对“收集”有特定定义，本地处理与仅为实时请求临时处理存在区别。不能因为开发者没有服务器，就直接填写“未收集数据”；应核对集成 SDK、预设 API 服务、实际保留行为，并就用户自定义 endpoint 的申报边界向 Apple 说明。第三方发送同意与商店标签是两项要求。

**Apple 构建与真机证据：**`doc/ios/README.md`记录已有完整 Debug/模拟器及部分 Profile 签名构建证据，不能继续概括成只有语法检查；但真实服务、配对真机、后台语音长请求和 Release/App Store 签名仍需验证。本次没有重新构建或验证这些记录。应检查最终 Archive 中 Flutter/插件的[隐私清单及 Required Reason API](https://developer.apple.com/support/third-party-SDK-requirements/)。复杂功能扩展仍按既有决定关闭，不作为首发承诺。

## 中国大陆：两类手续与实际产品边界

### App 备案

[工信部 App 备案通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)针对境内从事互联网信息服务的 App 主办者；[Apple 中国大陆供应说明](https://developer.apple.com/cn/help/app-store-connect/reference/app-information/app-information/)要求适用应用填写可验证的 ICP 备案信息，元数据与备案匹配。

网站备案、App 备案、经营性 ICP 许可证、AI 模型备案、AI 应用登记不是同一事项。不能用网站备案号替代 App 手续，也不能认定所有 AI App 一律需要经营性 ICP 许可证。AI Link 联网调用第三方且没有自有服务端，其办理路径与是否适用某种边界需向主办者所在地通信管理局核实，不能自行声称纯工具免备案。

### 生成式 AI 备案/登记

[《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)以向境内公众提供生成服务为适用范围；具有舆论属性或者社会动员能力的服务涉及安全评估和算法备案。个人自用实验与面向公众发行不同，不自训模型并不直接排除应用层义务。

[网信办 2026-09-14 公告](https://www.cac.gov.cn/2026-09/14/c_1791136833136332.htm)明确：通过 API 等方式调用已备案模型的生成式 AI 应用或功能，由地方网信办登记；已上线应用需公示所用模型的备案号或上线编号。

对 AI Link 的判断：没有在本次公开资料中找到“自备 Key、设备直连、任意 endpoint”专门豁免。不能承诺一定要进行模型训练级备案，也不能承诺完全不用登记。决定性问题是此类开放客户端在属地监管中的角色及登记范围。

当前预设同时有国内、境外服务，任意模型/地址让服务范围难以固定，也无法保证模型来源、内容治理和登记信息始终一致。国内 API 服务商的某项模型已备案，并不意味着该商家全部模型或 AI Link 自动覆盖。更可落地的大陆方案是限定实际可用的服务与模型，取得适用手续，并与提供商落实安全处置分工。仅从商店文案删除境外名字，或仅隐藏入口而仍可恢复任意调用，不能据此认定风险已解决。

### 生成内容与数据保护

[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)自 2025-09-01 施行，适用主体涉及文本/音频显式标识及文件隐式标识；下载、复制、导出也有要求。当前设置内已有“朗读声音由 AI 生成”，但聊天来源信息可隐藏，`lib/message_copy.dart`复制正文不主动添加 AI 标识。若适用，应具体核对聊天界面、播放界面与复制内容；在设置中有一句说明不等于实现完成。文件/剪贴板的技术要求及责任分工须结合强制标准进一步确定。

[《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)及[跨境数据规定](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm)涉及境外接收方告知、单独同意、影响评估和适用的出境机制。直接请求意味着数据仍可能离开境内；无开发者中转不代表不存在数据传输。AI Link 是否作为相关个人信息处理者、用户自选服务的责任边界及规模豁免，应按实际控制目的/方式判断，不能笼统断言所有请求必须申报安全评估，也不能认为一个弹窗就完成全部要求。

此外，[2026-07-15 起施行的拟人化互动办法](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)明确排除不涉及持续情感互动的知识问答、工作助手等。AI Link 当前通用工具定位较适合；若以后加入持续性情感陪伴、AI 恋人等功能或宣传，应另行评估。

## 境外服务和欧盟

App 可下载、API 在当地获准使用、网络实际可达是三个不同问题。

- [OpenAI API 支持地区](https://help.openai.com/en/articles/5347006-openai-api-supported-countries-and-territories)目前未列中国大陆，且说明从未支持地区访问或提供访问可能导致停用。不要宣称境内可直接稳定使用。
- [Anthropic 支持地区](https://www.anthropic.com/supported-countries)同样未列中国大陆；[其销售限制说明](https://www.anthropic.com/news/updating-restrictions-of-sales-to-unsupported-regions)还涉及受不支持地区控制的组织。用户自己的 Key 与开发者自己购买额度再转售是不同安排；这是第三方合同与供应风险，不是苹果禁止中国开发者的证据。应核实预设接入与主体的具体授权边界。
- 面向欧盟提供服务，要核对[GDPR 适用性](https://commission.europa.eu/law/law-topic/data-protection/information-business-and-organisations/application-gdpr_en)。本地保存能减少部分数据处理，但不会自动解决第三方传输的角色、依据与权利请求问题。
- [欧盟 AI 透明度义务](https://digital-strategy.ec.europa.eu/en/library/guidelines-transparency-obligations-providers-and-deployers-ai-systems)从 2026-08-02 起适用。第 50 条区分用户知情、生成输出机器可读标识及特定传播情形，存在例外；不能直接照搬成每条普通聊天必须弹窗。应先确定 AI Link 在系统中的角色，并设计清晰 AI 身份提示、保留供应商标识。它没有自训模型，不应未经分析就套用通用模型训练提供者的全部义务。
- [Apple 的欧盟 DSA 流程](https://developer.apple.com/cn/help/app-store-connect/manage-compliance-information/manage-european-union-digital-services-act-trader-requirements)需要申报交易商身份；被认定为交易商时需验证并公开地址、电话、邮箱。个人开发者不当然等于非交易商。

## 上架准备顺序

1. 补第三方数据同意：按接收方/域名管理，说明文字和语音流程；让手机与手表执行一致的许可状态，撤销后停止对应网络请求。
2. 更新并公开 iOS/watchOS 隐私政策，核对商店标签、权限描述、SDK 隐私清单。
3. 提供审核可用的限额凭据、配置步骤及真实演示；完成真实 iPhone/Apple Watch 语音、同步、失败恢复及 Release 验证。
4. 将应用描述定位为自有 API 客户端，准确说明 API 费用与配置要求；在无付费功能阶段保持收费流程简单。
5. 境外按地区逐步发行；欧盟身份、数据保护与 AI 透明度核查完成后开放。
6. 大陆先向所在地通信管理局、网信办确认开放客户端的 App 备案/AI 登记路径；得到边界后确定服务范围，并实现适用的 AI 标识和反馈处置。

本次仅新增调研文档和目录查询证据，没有修改现有功能、线上政策或提交任何商店审核。实际大陆分类、任意 endpoint 的义务边界以及具体第三方合同适用性，仍需用确定的运营主体和发行方案向主管机关及相应专业顾问核实。
