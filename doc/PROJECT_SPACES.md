# 项目空间、轻量知识库与历史搜索

## 入口与行为

手机会话抽屉、桌面会话侧栏均提供「搜索标题和消息」及项目筛选入口。「全部对话」覆盖所有项目，「未分组对话」只显示没有项目的会话。项目列表可创建、管理和选择项目；选择项目后，未发送的草稿同步归入该项目；若正在查看其它项目/未分组的已有会话，则进入所选项目的新草稿，保留已输入的文字与附件，不移动旧会话。侧栏按钮、聊天「更多 → 新对话」和桌面新对话快捷键均沿用当前筛选的项目；「全部对话」或「未分组对话」下新建会话归入未分组。聊天顶部显示当前项目，点击可管理。筛选保存在聊天页，关闭/重建抽屉或切换窗口宽度不丢失；选择项目返回后，窄窗口/手机自动重新打开筛选后的会话抽屉。

聊天页「更多」支持「添加到项目」或「移动到项目」，也适用于未发送的新会话草稿。草稿只改变归属，不提前创建空会话，也不清空文字和附件；第一条消息发送时一起保存项目归属。已有会话移动后，侧栏同步切换目标项目。选择期间切到其它聊天会取消原聊天的归属操作，生成/录音/转写/选附件期间不提供该入口。

会话操作菜单支持置顶/取消置顶、移动项目、重命名和删除。置顶持久化并排在普通会话前，不改写聊天正文。移动项目后，下一次请求使用目标项目的说明、记忆与知识库；已有消息和引用快照保留。生成中的会话不能从菜单移动项目。删除项目须确认：移除项目说明、记忆及知识文件，保留会话并移到未分组，不删除聊天附件原件或应用私有副本。

历史搜索在本机 SQLite 查询标题和消息正文，支持项目过滤；`%`、`_`、反斜杠作为普通字符匹配，不作为 SQL 通配符。最多返回 100 条，置顶优先，同组按最近会话和最新消息排序。点击正文匹配结果调用聊天已有的消息定位/高亮路径；只有标题匹配时打开会话。空搜索恢复会话列表。搜索文字不发送给外部服务。

## 项目说明与记忆

项目名称最多 60 字符，项目说明最多 8,000 字符，项目记忆最多 4,000 字符。说明在全局、单模型提示词后追加；项目记忆是用户手动维护的背景/偏好，以资料形式提供。

手机和桌面的项目对话不读取或更新全局跨会话记忆。切入项目会话时不自动总结到全局；全局总结写回事务也检查会话仍未归入项目。移动会话、删除项目时推进该会话的记忆游标，避免离开项目后重新总结此前的项目历史。此前已经存在于全局资料中的内容不自动撤回，用户可在记忆设置中编辑。项目记忆本版不自动总结。

项目内容不加入自动标题、联网搜索词、语音朗读或手表配置同步。手表保留原来的文字/语音链路，没有项目管理或知识检索入口；不把手机/桌面验证称为手表功能验收。

## 轻量知识库

每个项目拥有独立知识文件，可导入 UTF-8 文本（TXT、Markdown、代码、CSV 等）或新建知识笔记。按内容验证 UTF-8 和控制字符，拒绝空文件与 PDF 内容，不执行脚本、宏或公式。导入源文件不修改；仅将文本及本地检索分段保存到 SQLite，不另存一份聊天附件。

每份文档最多 200,000 UTF-16 代码单元、2 MiB；名称最多 255 字符。每项目最多 50 份、10 MiB UTF-8 正文。导入流在解码前限量，数据库事务同时校验项目容量、写入正文与分段。新建资料会同时保存当前项目表单；返回/取消文件选择不创建资料。知识库限制与聊天附件的 9 个、单个 30 MiB、请求总量 90 MiB 是不同入口的限制，界面分别说明。

按 Unicode 码点分为 600 字符片段，相邻重叠 150 字符。结合当前及上一条用户问题，提取英文词与中文双字词，在当前项目的文件名和片段中进行本地词项匹配并排序。最多选取 6 段，估算预算为上下文窗口的五分之一，上限 2,400 Token；整次请求仍由原有上下文预算守卫校验。没有匹配时不附加知识正文。

这是本地关键词检索，未使用向量模型、Embedding API、远端向量库或语义重排。不会保证找到同义改写或完全无关键词重合的段落。PDF、Office、图片解析/OCR 不在本版知识索引范围；它们仍可走现有聊天附件入口。

命中片段以 JSON 引用资料追加到最新用户消息，系统提示明确其为不可信资料、不能作为指令执行；不混进用户自己编写的项目说明。服务商模型仍需正确遵守这项约束，文档内容不能当作可靠指令。OpenAI 兼容和 Claude 均复用同一引用文本，保留现有 `stream_options` 兼容重试。

每段有稳定标签 `[K文档ID-段号]`。界面称为「提供给模型的资料」，不声称模型一定引用或正确理解了所有片段；可展开文件名并打开具体段落。随助手消息保存当时提供的片段快照，删除知识文档或项目后仍可核对历史回答。删除对应会话或清空本地数据会移除这些历史片段。

## 数据与隐私

SQLite v7 增加 `projects`、`knowledge_documents`、`knowledge_chunks`；topics 新增可空 `project_id` 和默认 0 的 `pinned_at`，messages 新增可空 `knowledge_sources`。v6 升级只增加表、列和索引，旧会话为未分组且未置顶。外键级联删除知识索引；删除项目的会话外键设为 NULL。

项目说明、记忆、知识正文和历史片段以明文保存在设备本地数据库。聊天时，项目提示词和命中的片段直接交给当前选定的模型服务；开启联网搜索仅发送原问题文字，不向搜索服务发送项目资料。API Key 继续使用安全存储。没有账户、跨设备同步或自有中转服务。应用内三语言隐私说明已补充；官网隐私政策未在这次任务中发布。

## 数据库版本标记回退的恢复

缺少 `onDowngrade` 回调的旧构建重新打开新数据库时，sqflite 可能降低 `PRAGMA user_version`，但保留新的表和列。之后再升级，原来的直接建表或加列会报 `table projects already exists` / duplicate column。当前迁移对表和索引使用 `IF NOT EXISTS`，加列前检查 `PRAGMA table_info`，只补缺失对象；正常升级和版本标记回退均在原有升级事务内完成，不删除、覆盖或重建已有数据。数据库版本仍为 7。新版遇到高于自身支持的数据库时明确拒绝降级，不清空数据。

`test/project_schema_recovery_test.dart` 复现旧构建将 v7 标记退回 v5 后的重新升级，核对服务、设置、项目、记忆、知识正文/分段、会话与消息保留，并确认恢复后可保存模型配置；同时检查部分项目结构的补齐与重复执行。`test/database_downgrade_test.dart` 检查较新版本库被拒绝后版本和数据不变。既有数据库通道桩补上了表结构查询响应。

`integration_test/database_recovery_smoke_test.dart` 使用 macOS 原生 sqflite_darwin，在本次创建的独立临时目录复现 v7→旧构建标记 v6→新版恢复，逐表比较数据，并验证恢复后的服务配置保存。临时覆盖仅作用于测试引擎的数据库目录，结束恢复原路径，不打开正常应用数据库、不访问 API Key、不请求模型服务。运行前先单独构建对应测试入口，再通过现有驱动执行。完成后需重新构建 `lib/main.dart` 普通入口。静态分析通过，全套 352 项测试通过、1 项跳过；原生 macOS 恢复与保存回归通过。尚未直接检查或修改用户正在运行的实际数据库。

## 项目内首条消息归属回归

项目筛选与当前草稿归属必须同步，不能只过滤列表。发送前捕获当前项目及聊天位置，异步读取密钥和提示词后再次校验，首条消息与项目归属在同一事务写入。切换项目时不自动移动已保存的旧会话；此前因缺少归属而保存在未分组的聊天，可从聊天「更多 → 添加到项目」移动。
